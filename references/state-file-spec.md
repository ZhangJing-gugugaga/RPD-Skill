# 项目状态文件规范（.project-state.md）

## 概述

`.project-state.md` 是 RPD Skill 的核心持久化文件，记录项目的 PRD 摘要、功能进度、关键决策和阻塞项。它是跨 agent、跨会话的唯一真相来源。

## 文件格式

### YAML Frontmatter

文件必须以 YAML frontmatter 开头，用 `---` 分隔：

```yaml
---
name: my-project          # 必填，小写 kebab-case
created: 2026-06-05       # 必填，YYYY-MM-DD
last-synced: 2026-06-05T14:30:00  # 必填，ISO 8601
status: in-development    # 必填，planning|in-development|paused|completed
entry-type: new-idea      # 必填，new-idea|half-finished|continued
---
```

### 正文结构

正文使用标准 Markdown，包含以下章节：

1. **# 项目状态：[项目名]** — 标题
2. **## 一句话定义** — 产品核心定义
3. **## PRD 摘要** — 核心功能、排除项、商业模式、技术栈
4. **## 功能进度清单** — 表格形式的功能状态追踪
5. **## 关键决策记录** — 已做出的技术/产品决策
6. **## 诊断记录** — 三视角诊断的用户回答摘要
7. **## 当前阻塞项** — 待解决的问题
8. **## 技术栈** — 技术选型详情
9. **## 变更日志** — 状态文件的变更历史

### 功能进度清单格式

```markdown
| 功能 | 子任务 | 优先级 | 状态 | 备注 |
|------|--------|--------|------|------|
| 功能名 | 子任务名 | P0/P1/P2 | ✅ 已完成 / 🔨 进行中 / ⏳ 未开始 | 补充说明 |
```

**子任务字段说明**：
- 必填，即使只有一个子任务也需填写"默认"
- 支持嵌套：用 `>` 表示层级（如 `OAuth > Google`）
- 子任务粒度：一个独立可测试的交付物

**示例**：
```markdown
| 功能 | 子任务 | 优先级 | 状态 | 备注 |
|------|--------|--------|------|------|
| 用户登录 | 表单提交 | P0 | ✅ 已完成 | |
| 用户登录 | OAuth > Google | P0 | 🔨 进行中 | 70% |
| 用户登录 | OAuth > GitHub | P0 | ⏳ 未开始 | |
| 用户登录 | 密码重置 | P1 | ⏳ 未开始 | |
```

### 状态标记规则

- ✅ 已完成：功能有完整实现，可正常使用
- 🔨 进行中：有部分代码但未完成
- ⏳ 未开始：PRD 中定义但无代码

### 关键决策记录格式

```markdown
| 日期 | 类型 | 决策 | 原因 | 影响范围 |
|------|------|------|------|----------|
| MM-DD | 类型 | 具体决策 | 决策原因 | 影响的模块/层级 |
```

**类型字段可选值**：
- 技术选型（技术栈、框架、数据库等）
- 架构模式（分层、微服务、状态管理等）
- 安全策略（认证、加密、权限等）
- 业务逻辑（规则、流程、算法等）
- 其他

**示例**：
```markdown
| 日期 | 类型 | 决策 | 原因 | 影响范围 |
|------|------|------|------|----------|
| 06-03 | 技术选型 | 用SQLite而非PostgreSQL | 单机部署 | 数据层全局 |
| 06-04 | 架构模式 | 采用状态机管理登录流程 | 避免状态爆炸 | 认证模块 |
| 06-05 | 安全策略 | 实施JWT双token机制 | 提升安全性 | 认证+API层 |
```

### 诊断记录格式

```markdown
| 轮次 | 视角 | 问题 | 用户回答摘要 |
|------|------|------|-------------|
| R1 | 用户 | 目标用户是谁？ | 独立开发者，自己用 |
| R2 | 商业 | 如何盈利？ | 免费+增值 |
| R3 | 技术 | 技术栈？ | React + Node.js |
| R4 | 安全 | 涉及支付吗？ | 暂不涉及 |
```

**字段说明**：
- 轮次：R1/R2/R3/R4，分别对应用户/商业/技术/安全四轮诊断
- 视角：用户/商业/技术/安全
- 问题：诊断轮次中的核心问题
- 用户回答摘要：用户回答的关键信息（≤50字）

**示例**：
```markdown
| 轮次 | 视角 | 问题 | 用户回答摘要 |
|------|------|------|-------------|
| R1 | 用户 | 目标用户是谁？ | 独立开发者，自己用 |
| R2 | 商业 | 如何盈利？ | 免费+增值 |
| R3 | 技术 | 技术栈？ | React + Node.js |
| R4 | 安全 | 涉及支付吗？ | 暂不涉及 |
```

## 更新时机

1. **初始化**：新项目流程完成 PRD 后自动生成
2. **接手项目**：半成品流程分析代码后自动生成
3. **手动更新**：用户说"更新进度"时，Agent 更新功能状态
4. **自动提醒**：开发完一个功能后，Agent 提醒用户更新

## 校验规则

状态文件必须通过 `state-validator.py` 的 JSON Schema 校验：
- 必填字段不可缺失
- status 必须是 planning/in-development/paused/completed 之一
- entry-type 必须是 new-idea/half-finished/continued 之一
- 日期格式必须正确
