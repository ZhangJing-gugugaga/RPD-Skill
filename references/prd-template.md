# PRD 模板

## 概念版 PRD（≤ 200 字）

核心用户：[一句话描述目标用户]
要解决的一件事：[一个具体痛点，不能写多个]
产品形态：[平台]
最小可用版功能（≤ 3 条）：
  1. [功能一]
  2. [功能二]
  3. [功能三]
本版本不做：[明确排除的功能]
商业模式：[收费方式 或 免费]
技术前提：[账号体系 / 数据方案 / 第三方依赖]

## 五、六大盲区自检清单

- [ ] **页面结构**：每个主要页面的职责、元素、不展示内容是否明确？
- [ ] **异常交互**：每个功能的用户流程是否包含异常路径？
- [ ] **状态机**：所有状态是否完整列出？进入和退出条件是否明确？
- [ ] **字段规范**：每个输入字段是否有类型、必填、长度、校验规则、错误提示？
- [ ] **文案规范**：空状态、加载、成功、失败、权限、网络异常六类文案是否齐全？
- [ ] **流程图**：用户流程是否包含分支和异常分支？

## 六、安全设计自检清单

> 以下清单覆盖 Vibe Coding 场景中最常见的安全盲区。每个功能模块都应逐项检查。

### 账户安全
- [ ] **短信/邮件验证**：是否有人机验证（图形验证码/滑块）？
- [ ] **频率限制**：单手机号/IP 每日发送上限是多少？
- [ ] **全局熔断**：是否有全局限频防止资源耗尽？

### 内容安全
- [ ] **UGC 审核**：用户头像、昵称、评论等内容是先审后发还是先发后审？
- [ ] **机审方案**：是否接入内容安全API（网易易盾/阿里云/腾讯天御）？
- [ ] **人工审核**：机审疑似案例的人工复核流程是什么？

### 文件安全
- [ ] **文件类型限制**：上传功能是否限制了允许的文件类型？
- [ ] **文件大小限制**：是否有单文件和总量限制？
- [ ] **存储方案**：使用云对象存储还是本地磁盘？
- [ ] **防盗链**：是否有 Referer/签名校验？

### AI 安全
- [ ] **Prompt 保护**：System Prompt 是否从代码中分离？
- [ ] **泄露防护**：是否有防角色扮演、防复述指令的措施？
- [ ] **模型信息**：是否暴露了底层模型名称/提供商？

### 传输安全
- [ ] **HTTPS**：全站是否强制 HTTPS？
- [ ] **敏感数据**：密码、token 是否加密传输？
- [ ] **CORS**：跨域策略是否正确配置？

### 基础设施安全
- [ ] **环境变量**：密钥是否通过环境变量注入，而非硬编码？
- [ ] **依赖审计**：是否有定期的依赖漏洞扫描？
- [ ] **日志脱敏**：日志中是否包含敏感信息？

自检通过后，输出："PRD 落地版已完成，六大盲区 + 安全设计 + AI 增强 8 大区块均已覆盖。"

### 七、问题校验（AI 增强）

> 在进入功能设计前，先校验需求的"问题质量"。以下任一问题未通过，先回炉澄清，再继续填写。

- [ ] **目标用户是否太泛**：[例如"所有人"→ 应缩小为可触达的细分人群；写明用户画像]
- [ ] **MVP 是否过大**：[功能列表是否超过 3-5 个核心能力？超出部分移入 v2 停车场]
- [ ] **需求是否单一**：本版本是否只解决"一件事"？多件事请拆分
- [ ] **验证可行性**：技术前提 / 账号体系 / 第三方依赖是否已确认存在？

### 八、输入设计（AI 增强）

| 输入项 | 来源 | 类型 | 是否必填 | 约束/校验规则 | 示例 |
|--------|------|------|----------|---------------|------|
| [输入项] | [用户输入/系统/第三方] | [文本/文件/语音] | 是/否 | [长度/格式/范围] | [示例值] |

- [ ] 输入缺失时是否给出兜底提示？
- [ ] 输入异常（空 / 超长 / 格式错）的处理路径是否已定义？

### 九、输出设计（AI 增强）

> 明确 AI 功能输出什么、以什么形式展示、**用户看完后能做什么动作**。

| 输出内容 | 展示形式 | 用户看完后能做什么动作 | 输出时机 |
|----------|----------|------------------------|----------|
| [输出] | [文本/卡片/列表] | [例如：一键复制 / 直接使用 / 跳转编辑] | [实时/异步] |

- [ ] 输出结果是否有空态 / 失败态？
- [ ] 输出内容是否需要人工复核（AI 幻觉风险）？

### 十、AI Workflow 设计（AI 增强）

> 画出 AI 功能的完整工作流（触发 → 输入 → AI 处理 → 输出 → 兜底），流程图中每个分支都要有出口。

```
[触发入口]
  ↓
[输入收集 / 校验]
  ├─ 通过 → [调用 AI（模型/接口）]
  │         ├─ 成功 → [解析结果] → [输出展示]
  │         └─ 失败 → [重试 / 降级方案]
  └─ 未通过 → [提示用户修正]
```

- [ ] 每个分支（成功 / 失败 / 超时 / 降级）是否都有出口？
- [ ] AI 响应超时 / 中断的处理策略是什么？

### 十一、AI 职责拆解（AI 增强）

## 十五、AI PRD 自检清单

> 落地版 PRD 完成后，逐项确认 AI 增强章节是否齐备、可执行。

- [ ] **问题校验**：目标用户、MVP 范围、需求单一性是否已校验？
- [ ] **输入设计**：每个 AI 输入项的来源、必填、校验规则是否明确？
- [ ] **输出设计**：每个 AI 输出是否写明"用户看完后能做什么动作"？
- [ ] **AI Workflow**：AI 工作流是否包含完整分支（成功 / 失败 / 超时 / 降级）？
- [ ] **AI 职责拆解**：AI 任务是否用具体动词描述（抽取 / 分类 / 匹配 / 排序 / 生成）？
- [ ] **Badcase 分析**：是否至少列出 8 个边界场景及应对策略？
- [ ] **验证目标**：每个 AI 输出是否有可测量的通过标准？
- [ ] **PRD 风险和下一步**：未决风险、不确定性、下一步行动是否已记录？
